## [추가] RG32.ipynb — 팀 공통 전처리 파일 기준 재분석

팀 공통 전처리 파일(`2_Preprocessed_Data.csv`)을 기준으로 전처리 검증 → 모델링을 다시 수행했다. 실행 결과가 저장되어 있다.

**1. 전처리: 설명대로 다시 계산해 `data/2_Preprocessed_Data.csv`를 덮어씀**
(`Final_Deliverables_RG3/2_Preprocessed_Data.csv`와 값이 다르다. 열 이름·순서·행 순서는 동일)

| 항목 | 팀 공통 파일 | RG32 (설명대로) |
|---|---|---|
| `Virtual_ID` | 행 순서 짝·홀 (8쌍은 두 부품이 같은 번호) | 같은 샷에서 먼저 기록된 부품 0, 나중 부품 1 |
| `_EMA10` / `_EMA3` | 행 기준 (실제 약 5샷 / 1.5샷) | 샷 기준 최근 10샷 / 3샷 |
| `_DIFF` | 현재값 − EMA10 | 직전 샷 대비 변화량 |

**2. 모델: 샷 단위로 묶은 5-fold × 10 (같은 샷의 두 부품이 학습·평가로 갈리지 않게)**

| 모델 | 검사 50% 시 불량 포착 | F1 / Precision / Recall | ROC-AUC |
|---|---|---|---|
| `Virtual_ID` 기반 단일 변수 규칙 (캐비티별 불량률, OneR 방식) | 0.92 | 0.075 / 0.039 / 0.92 | 0.72 |
| 공정 변수만 (HGB) | 0.44 | 0.028 / 0.016 / 0.33 | 0.47 (라벨 순열과 같음, p = 0.52) |
| 공정 + `Virtual_ID` (HGB) | 0.67 | 0.036 / 0.023 / 0.20 | 0.62 |
| 무작위 검사 | 0.50 | — | 0.50 |

- 공정 변수 47개(원 센서 + EMA·DIFF)는 `Virtual_ID` 위에 정보를 더하지 못했다 (공정값을 샷끼리 섞은 귀무분포보다 낫지 않음).
- **⚠ 결론은 `Virtual_ID` = 실제 캐비티 위치라는 가정에 기댄다.** 원본에 캐비티 식별자가 없어 확인되지 않았고,
  팀 CN7 보고서(`Final_Deliverables_CN7`, 2026-09-29 수정)는 `Virtual_ID`를 물리적 위치로 보지 않는 입장이다.
  이 가정이 성립하지 않으면 RG3의 결론은 "공정 데이터로는 부품 단위 불량 예측 불가 → 샷 단위 검사 또는 전수검사"가 된다.
- 결과표: `outputs/tables/model_comparison_RG3.csv`(팀 공통 형식), `m_final_performance.csv`, `feature_importance_RG3.csv`

## 핵심 결과 (RG3.ipynb)

| 방법 | 재현율 1.0에 필요한 검사율 | 검사 50%일 때 재현율 | ROC-AUC |
|---|---|---|---|
| 무작위 | 97% | 0.50 | 0.50 |
| **쌍 순서 규칙 (최종)** | **84%** | **0.92** | **0.71** |
| Isolation Forest (공정 값) | 99% | 0.48 | 0.48 |
| 오토인코더 (공정 값, 가이드북 방법) | 98% | 0.62 | 0.52 |

1. **검사 우선순위 = 부품 위치(쌍의 앞쪽 먼저)** — 검사 50%로 불량 25개 중 23개(92%)를 잡는다 (이항검정 p = 1.9e-05). 교차검증·시간 순 검증에서 방향이 유지된다.
2. **재현율 1.0이 필수라면 사실상 전수검사** — 검사를 줄이면 임계값을 정할 때 쓰지 않은 샷에서 재현율 1.0 달성 비율이 68~80%에 그친다.
3. **공정 값 23개로는 불량을 구분할 수 없다** — 이상탐지(IF·오토인코더), 정답을 준 지도학습(로지스틱·랜덤포레스트), 전처리 변경 모두 무작위 수준 (순열검정 p ≥ 0.65).

## ⚠ 중요한 가정: 쌍 순서의 의미

labeled 데이터는 공정 값이 똑같은 행이 **정확히 2개씩** 짝을 이룹니다 (한 번 사출에 부품 2개, LH/RH로 추정). 결론 1은 이 쌍의 순서(`pair_pos`)가 **부품 위치**라는 가정에 기댑니다.

- 순서가 **검사 결과의 기록 순서**라면(예: 불량을 먼저 입력) 이는 정답 누수이고, 결론은 "전수검사"로 바뀝니다.
- CN7도 같은 쌍 구조와 앞쪽 치우침(13/17)이 있어 이 가능성을 배제하지 못합니다.
- **확인 방법**: KAMP 원본 1차 가공 데이터(`labeled_data.csv`)의 `PART_NAME`·`TimeStamp`로 쌍 순서가 LH/RH와 일치하는지 확인 (노트북 3-7, 8-2 (e) 참고).

## 실행 방법

Python 3.12 기준, 전체 실행 약 3분.

```bash
cd 1_RG3_2
python -m venv .venv
.venv\Scripts\activate          # 맥/리눅스: source .venv/bin/activate
pip install -r requirements.txt
jupyter notebook RG3.ipynb      # 또는 VS Code에서 열고 커널로 .venv 선택
```

- 노트북은 **위에서부터 순서대로** 실행해야 합니다 (앞 섹션의 변수를 이어서 사용).
- 3-4 역변환 셀은 약 1분, 6-6 순열검정 셀은 약 1.5분 걸립니다.
- 난수 시드는 `SEED = 42`로 통일되어 있어 결과가 재현됩니다.
- 한글 글꼴은 맑은 고딕(윈도우) / AppleGothic(맥) / 나눔고딕(리눅스) 중 설치된 것을 자동으로 씁니다.
