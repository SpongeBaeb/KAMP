# ⑤ 전력사용량 예측 및 최대피크 위험조건 분석 — v2 재분석

v1(상위 폴더의 experiment_*.py, Final_Report)에 대한 검토 지적을 반영해 처음부터 다시 분석했다. v1 파일은 그대로 두었다.

| v1 지적 | v2 반영 |
|---|---|
| 예측 구간 정의 없음 (1시간 앞 모델을 "익일 24시간"으로 제시) | H1(1시간 앞)과 H24(익일 24시간)를 따로 정의·평가 |
| 상위 1% 피크를 학습·평가에서 제거 | 피크 포함 평가 + 피크 시간만의 오차를 따로 보고 |
| 비교 기준선 없음 (33.03은 초기 LSTM) | 직전 1시간·전날·전주·최근 7일 평균 기준선과 비교 |
| 전체 데이터로 특징 선택 후 교차검증 | 특징 목록을 미리 고정, 선택 단계 없음 |
| 등각 구간의 실제 포함률 미확인 | 평가 달에서 90% 구간 포함률 확인 |
| 오차 조건을 최종 모델이 아닌 간이 모델로 분석 | 최종 모델 예측 오차를 생산·운영 조건별로 집계 |
| 피크 규칙이 현재값 포함 이동평균(Peak_MA3)으로 피크를 설명 | 전력값은 빼고 운영 변수만으로 설명 |
| 저감 방안·절감액 근거 없음 ("25% 절감") | 15분 수요로 가동 시점 이동 시뮬레이션, 한전 단가로 절감액 계산 |
| (추가 발견) 2021-07-13, 07-15의 `시간` 열에 전력값이 들어 있음 | 그날 행 순서로 0~23시 복구 (`prep.py`) |

## 실행

```bash
cd "⑤ Electricity Consumption Prediction/v2"
python forecast.py     # 예측 평가 → outputs/forecast_*.csv
python conditions.py   # 오차 조건·피크 조건 → outputs/error_conditions.csv, peak_*.csv/txt
python peak_shift.py   # 피크 저감 시뮬레이션 → outputs/peak_shift_simulation.csv
```

데이터: `../okm_augumented_2021.csv` (KAMP 「자원 최적화 AI 데이터셋」 원본, 2021-01-01~09-14, 257일 × 24시간). 타깃 Peak = 그 시간 15분 수요 4개 중 최댓값.

## 1. 예측 (월 단위 전진 검증: 4~9월 각 달을 평가, 그 이전 전체로 학습)

| 구간 | 방법 | RMSE (kW) | 피크 시간 RMSE | 90% 구간 실제 포함률 (전체 / 피크) |
|---|---|---|---|---|
| H1 | 기준: 직전 1시간 | 23.3 | 44.9 | — |
| H1 | LightGBM (달력) | 14.2 | 31.0 | 79% / 62% |
| H1 | LightGBM (달력+계획) | **13.9** | 30.1 | 80% / 64% |
| H24 | 기준: 전날 같은 시각 | 66.5 | 80.4 | — |
| H24 | 기준: 전주 같은 시각 | 36.0 (월별 10.5~76.3) | 74.0 | — |
| H24 | LightGBM (달력) | 39.6 | 64.0 | 86% / 68% |
| H24 | LightGBM (달력+계획) | **29.3** | 51.2 | 85% / 66% |

- 피크 시간 = 학습 기간 상위 5% 이상. "계획"은 생산량·인원·기온을 미리 안다고 가정하고 실측값을 쓴 것이라 실제 운영보다 낙관적이다.
- H1은 기준선보다 40% 낮다. H24는 생산 계획을 넣어야 전주 기준선을 넘는다. 단 6·7·9월은 전주 기준선이 더 좋다(주간 일정이 반복된 달).
- 일 최대수요 오차(MAE): LightGBM(달력+계획) 23.5 kW, 전주 같은 시각 25.6 kW.
- 90% 구간은 실제로 79~86%만 포함하고, 피크 시간에는 62~68%다 → 피크 경보용으로는 구간을 넓히거나 피크 시간 전용 보정이 필요하다.

## 3. 최대전력 피크 발생 조건 (운영 변수만, 피크 = 상위 5%, 187 kW 이상)

- **시각**: 피크의 대부분이 8~11시와 13~15시. 8시의 피크 비율이 24.5%로 가장 높다. 일 최대수요가 8시에 나온 날이 257일 중 90일, 월 최대수요 9번 중 6번이 8시(대부분 08:15).
- **생산량**: 생산량 300 이하에서는 피크 비율 0.6~1.4%, 301~800에서 10.4%, 801~1,500에서 17.4%.
- **요일**: 평일 6.8% vs 주말 1.4%.
- **기온**: 피크와의 상관은 0.05로 낮다. 결정나무에서는 생산량이 많고 17시 이후일 때만 기온 25.2℃ 초과가 피크를 가른다 (여름 오후 냉방).
- 가동일 8시 평균 155.6 kW, 비가동일 8시 49.2 kW. 7시 대비 8시 상승 폭 중앙값 26 kW → 가동 시작 시 설비가 한꺼번에 올라오는 패턴.
- 참고: 최대수요 222 kW가 4개 달에서 똑같이 나온다. 계측 상한일 가능성이 있어 확인이 필요하다.

## 4. 피크 저감 시뮬레이션 (`outputs/peak_shift_simulation.csv`)

같은 날 안에서 상한을 넘는 15분 부하를 앞뒤 1시간(또는 2시간) 안의 여유 구간으로 옮긴다고 할 때, 각 달 최대수요를 어디까지 낮출 수 있는지 계산했다.

| 월 | 현재 (kW) | ±1시간 조정 | 옮길 전력량 (kWh/월) | 조정 필요 일수 | ±2시간 조정 |
|---|---|---|---|---|---|
| 1 | 222 | 185 | 129.5 | 11 | 177 |
| 2 | 198 | 182 | 69.0 | 9 | 176 |
| 3 | 222 | 185 | 142.0 | 14 | 176 |
| 4 | 199 | 176 | 75.8 | 12 | 171 |
| 5 | 199 | 176 | 72.8 | 11 | 171 |
| 6 | 222 | 185 | 142.0 | 14 | 177 |
| 7 | 222 | 194 | 236.8 | 17 | 192 |
| 8 | 218 | 187 | 176.5 | 14 | 182 |
| 9 | 204 | 182 | 109.3 | 10 | 175 |

- 한 달에 70~240 kWh(하루 사용량의 일부)만 옮기면 최대수요를 16~37 kW 낮출 수 있다는 계산이다. 옮겨야 하는 구간은 대부분 8시대 가동 시작이다.
- **기본요금 영향**: 한전 요금적용전력은 해당 월과 직전 12개월 중 겨울철(12~2월)·여름철(7~9월) 최대수요 가운데 큰 값으로 알려져 있다(기본공급약관 원문으로 확인 필요). 9개월 전체에서 상한이 ±1시간 194 kW(7월), ±2시간 192 kW로 정해지므로 요금적용전력은 222 → 194 kW(−28 kW) 또는 192 kW(−30 kW)가 된다. 산업용(갑)Ⅰ 고압A 선택Ⅱ 기본요금 7,470원/kW(2023-05-16 시행 요금표)로 **연 약 251만~269만 원**이다.
- 한계: 설비별 부하와 공정 순서 제약을 모르므로 상한(최대치) 추정이다. 계약전력 기준으로 기본요금이 부과되는 계약이면 기본요금 효과는 없고, 최대수요 초과 위험만 줄어든다.

## 운영 제안

1. **가동 시작 분산**: 8시에 함께 켜는 설비를 7시대 후반~8시 사이에 15분 간격으로 나눠 기동 (위 시뮬레이션의 ±1시간 범위 안)
2. **H24 예측 + 생산 계획 연동**: 전날 생산 계획(가동 여부·생산량)을 넣어 익일 시간대별 수요를 예측하고, 상한(예: 194 kW)을 넘는 시간대를 미리 표시
3. **H1 경보**: 1시간 앞 예측이 상한에 가까우면 비필수 부하를 지연. 단 90% 구간이 피크 시간에 64%만 포함하므로 경보 기준은 예측값 + 구간 상단보다 보수적으로 잡는다
